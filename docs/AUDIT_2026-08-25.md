## 3. Biggest Findings

1. **~15-20 services are complete stubs** disguised by commit messages claiming "implementation"
2. **The `no_data_response` pattern** honestly signals unavailability but means features look like they exist while being non-operational
3. **Entity graph (core differentiator) is in-memory** — all relationship data vanishes on restart
4. **Only 2 Alembic migrations** for 55+ models — fresh Postgres deployments rely on `create_all` hack
5. **Intelligence test takes 226s and fails** — makes real external HTTP calls without mocking
6. **6 API modules use in-memory dicts** (support, status, freshness, editorial, experiments, SEO) — all data lost on restart
7. **`import random` fully removed** — the mock-data ban was genuinely enforced
8. **85% of services (76/90) never persist data** — pure compute/API-fetch, no caching
9. **Redis caching module exists but only 1 service uses it** — expensive external API calls are re-fetched every request
10. **Stripe billing has a bug** — `hmac.new` should be `hmac.HMAC` in webhook verification
11. **Insider activity returns real SEC Form 4 data** with 19 fields per transaction — genuine implementation
12. **7 services work without any credentials** (SEC EDGAR, yfinance, Yahoo Charts, GDELT, House Clerk, CoinGecko, Blockchain.info)
13. **`portfolio_analytics_service.py` falls back to hardcoded `DEFAULT_PORTFOLIO`** when DB fails — user analytics may show fake allocations
14. **OpenSecrets API deprecated (April 2025)** but code still present; FEC is replacement
15. **Previous audit (Aug 22) already reset claims from 90% to 25%** — latest commits claim "75%" but evidence shows 35-40%

## 4. Critical Broken Workflows

### Intelligence Report Generation (on fresh DB)
```
POST /intelligence/generate → intelligence_service.py
  → tries to INSERT into 'reports' table
  → ❌ sqlite3.OperationalError: no such table: reports
  → 500 error to frontend
```
**Fix:** Ensure `app.models.reports` is imported before `create_all` in startup (or run Alembic).

### Entity Graph Persistence
```
Background scheduler ingests SEC/FEC data → entity_graph_service._entities = {}
  → Server restart (deploy, crash, scale)
  → ❌ All entity/relationship data gone
  → User sees empty graph
```
**Fix:** Replace in-memory dicts with SQLAlchemy queries to existing Entity/Relationship models.

### Portfolio Analytics (DB failure path)
```
GET /portfolio-analytics/allocation → portfolio_analytics_service
  → _get_user_portfolio(user_id) → catches SQLAlchemyError
  → ❌ Returns DEFAULT_PORTFOLIO = {"AAPL": 0.2, "MSFT": 0.15, ...}
  → User sees fake portfolio weights without knowing
```
**Fix:** Raise the error to the user or return `no_data_response`.

### Brokerage Sync (entire flow)
```
User visits /brokerage → Frontend calls /brokerage/brokers
  → Backend: get_supported_brokers() → no_data_response("Plaid not configured")
  → ❌ Entire feature is a stub — zero real code
```
**Status:** Genuinely blocked by business decision (Plaid contract).

**2. Persist entity graph to PostgreSQL**
- Why: Core differentiator (relationship intelligence) vanishes on restart
- Affected: `apps/api/app/services/entity_graph_service.py`
- Fix: Replace `self._entities: Dict[str, EntityNode] = {}` with SQLAlchemy queries to Entity/Relationship models
- Verify: Create graph, restart server, query graph — data persists
- Complexity: High (1-2 days)

**3. Fix database migrations for production Postgres**
- Why: `create_all` hack fails for concurrent access and schema evolution
- Affected: `apps/api/migrations/versions/`
- Fix: Run `alembic revision --autogenerate` to capture all 55+ models
- Verify: `docker-compose up` from scratch, `alembic upgrade head` creates all tables
- Complexity: Medium (3-4 hours)

**4. Fix portfolio analytics hardcoded fallback**
- Why: User may see fake portfolio weights without any indication
- Affected: `apps/api/app/services/portfolio_analytics_service.py` line 28
- Fix: Remove `DEFAULT_PORTFOLIO` fallback, return `no_data_response` on DB failure
- Verify: DB failure path returns error to frontend, not fake data
- Complexity: Low (30 min)

## 10. Final Verdict

```

Previous audit claimed: 25-30% (Aug 22)
Verified completion: ~35-40%

Reason for 75% → 35-40% gap:
- 15+ services counted as "implemented" are 100% stubs returning "unavailable"

- Frontend page existence ≠ feature functionality
- Route registration ≠ data production
- The delta from 25% to 35-40% is real (yfinance, auth, scheduler, docker, mock ban)

1. Core data (entity graph) is lost on every restart
2. Primary workflow (intelligence reports) crashes on fresh databases  
3. Only 2 migration files exist for 55+ models
4. 15+ features advertised in the UI are complete stubs
5. No monitoring, no alerting, no deployment documentation
6. Test suite has failing/hanging tests

What IS genuinely good:
- Architecture is sound (FastAPI + SQLAlchemy + clean separation)
- Frontend-backend wiring is correct

- Real data flows exist for market data, SEC filings, FINRA
- The no_data contract is honest (vast improvement over fake random data)
- Background scheduler refreshes real external data
- Docker deployment configuration exists and should work
- External integration pattern is well-designed with graceful degradation

Path to production: ~2-3 weeks focused engineering on P0/P1 items,
```
